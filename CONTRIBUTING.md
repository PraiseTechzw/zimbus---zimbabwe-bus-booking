# Contributing to ZimBus

First off, thanks for taking the time to contribute! 🎉

The following is a set of guidelines for contributing to ZimBus, a online bus booking platform for Zimbabwe. These are mostly guidelines, not rules. Use your best judgment, and feel free to propose changes to this document in a pull request.

- [Code of Conduct](#-code-of-conduct)

## 📜 Code of Conduct

Help us keep the community healthy! Please be respectful and kind to others.

## 💡 How Can I Contribute?

### Reporting Bugs

- **Search first**: Check if the bug has already been reported.
- **Provide detail**: Include your OS, browser, and steps to reproduce.
- **Expected behavior**: Tell us what *should* have happened.

### Suggesting Enhancements

- **Explain the value**: How does this improve the user experience?
- **Provide sketches**: If it's a UI change, a simple mockup helps.

### Pull Requests

1.  **Fork the repo**: Create your own copy of the project.
2.  **Create a branch**: `git checkout -b feature/my-new-feature`.
3.  **Commit your changes**: `git commit -am 'Add some feature'`.
4.  **Push to the branch**: `git push origin feature/my-new-feature`.
5.  **Open a Pull Request**: Provide a clear description of your changes.

## 🎨 Styleguides

### Git Commit Messages

- Use the present tense ("Add feature" not "Added feature").
- Use the imperative mood ("Move cursor to..." not "Moves cursor to...").
- Limit the first line to 72 characters or less.

### JavaScript/TypeScript Styleguide

- We use **Prettier** for formatting.
- Components should be functional and use Hooks.
- Prefer **TypeScript** for better type safety.
- Keep components small and focused.

### CSS/Tailwind Styleguide

- Use **Tailwind CSS 4.0** utility classes where possible.
- Avoid custom CSS in `index.css` unless defining themes or global reusable patterns.
- Follow the design system (rounded corners, orange/gray palette).
